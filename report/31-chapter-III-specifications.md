| US02 | View subscription plans | As a Visitor, I want to see the available subscription plans so that I can evaluate service costs. | **Scenario 1:** Plan comparison.<br>**Given** that a visitor is evaluating service costs,<br>**When** they access the pricing section,<br>**Then** the system displays available plans with their features and prices.<br><br>**Scenario 2:** Currency localization.<br>**Given** that a visitor accesses the pricing section,<br>**When** the system detects the local region,<br>**Then** it displays the plan prices in the appropriate local currency. | EP01 |
| US03 | View problem statement | As a Visitor, I want to view the home care problem statement so that I can identify with the need for the service. | **Scenario 1:** Context identification.<br>**Given** that a visitor explores the general information,<br>**When** they reach the service context section,<br>**Then** the system presents the main challenges of continuous home care.<br><br>**Scenario 2:** Expanded details.<br>**Given** that a visitor is reading the problem statement,<br>**When** they request more information on a specific challenge,<br>**Then** the system expands the view to show detailed statistics. | EP01 |
| US04 | Learn about the Startup | As a Visitor, I want to read ByteCore's mission and vision so that I can understand the purpose behind the platform. | **Scenario 1:** Mission display.<br>**Given** that a visitor looks for company information,<br>**When** they access the corporate section,<br>**Then** the system displays the formal mission statement.<br><br>**Scenario 2:** Team visibility.<br>**Given** that a visitor is in the corporate section,<br>**When** they scroll to the team roster,<br>**Then** the system lists the founders and their roles. | EP01 |
| US05 | Consult legal terms | As a Visitor, I want to access the Terms of Service and Privacy Policies so that I can know how my medical data will be handled. | **Scenario 1:** Accessing Terms.<br>**Given** that a visitor navigates the platform footer,<br>**When** they select the terms of service,<br>**Then** the system presents the detailed legal document.<br><br>**Scenario 2:** Accessing Privacy Policy.<br>**Given** that a visitor navigates the platform footer,<br>**When** they select the privacy policy,<br>**Then** the system presents the data protection guidelines. | EP01 |
| US06 | Patient registration | As a Visitor, I want to register as a patient so that I can access monitoring tools. | **Scenario 1:** Successful registration.<br>**Given** that a visitor is on the registration view,<br>**When** they submit valid personal data,<br>**Then** the system creates a patient account and sends a confirmation email.<br><br>**Scenario 2:** Validation error.<br>**Given** that a visitor is registering,<br>**When** they submit the form with empty required fields,<br>**Then** the system halts registration and displays validation errors. | EP02 |
| US07 | Identify role-specific benefits | As a Visitor, I want to distinguish the benefits for both caregivers and patients so that I can understand how Vital Care helps each one. | **Scenario 1:** Caregiver perspective.<br>**Given** that a visitor views the target audience section,<br>**When** they select the Caregiver role,<br>**Then** the system highlights specific advantages like "Reduced anguish".<br><br>**Scenario 2:** Patient perspective.<br>**Given** that a visitor views the target audience section,<br>**When** they select the Patient role,<br>**Then** the system highlights advantages like "Independent living". | EP01 |
| US08 | Compare plan features | As a Visitor, I want to see a detailed comparison between the Basic and Premium plans so that I can choose the one that best fits my needs. | **Scenario 1:** Detailed list.<br>**Given** that a visitor navigates to the plans section,<br>**When** they compare the options,<br>**Then** the system clearly lists Premium-only features.<br><br>**Scenario 2:** Feature explanation.<br>**Given** that a visitor is viewing the comparison,<br>**When** they interact with a specific feature name,<br>**Then** the system displays a tooltip explaining the feature in detail. | EP01 |
| US09 | Login | As a User, I want to log into the platform so that I can access my private data. | **Scenario 1:** Successful login.<br>**Given** that a user is on the authentication view,<br>**When** they submit valid credentials,<br>**Then** the system grants access to the dashboard.<br><br>**Scenario 2:** Invalid credentials.<br>**Given** that a user is attempting to authenticate,<br>**When** they submit an incorrect password,<br>**Then** the system denies access and displays an error message. | EP02 |
| US10 | Password recovery | As a User, I want to recover my password so that I can regain access if I forget it. | **Scenario 1:** Valid request.<br>**Given** that a user requests recovery,<br>**When** they submit a registered email,<br>**Then** the system sends a secure reset link.<br><br>**Scenario 2:** Unregistered email.<br>**Given** that a user requests recovery,<br>**When** they submit an email not in the database,<br>**Then** the system displays a generic confirmation to prevent data enumeration. | EP02 |
| US11 | Update profile | As a User, I want to update my personal information so that my contact data stays current. | **Scenario 1:** Successful update.<br>**Given** that an authenticated user edits their profile,<br>**When** they submit valid new contact data,<br>**Then** the system updates the record successfully.<br><br>**Scenario 2:** Invalid format.<br>**Given** that an authenticated user edits their profile,<br>**When** they submit an incorrectly formatted phone number,<br>**Then** the system rejects the change and prompts for a valid format. | EP02 |
| US12 | View IoT synced metrics | As a User, I want to view the real-time health metrics synchronized automatically from the IoT patch so that I don't have to enter them manually. | **Scenario 1:** Active connection.<br>**Given** that the user has linked a valid patch,<br>**When** they access the patient dashboard,<br>**Then** the system displays the latest metrics automatically.<br><br>**Scenario 2:** Disconnected patch.<br>**Given** that the linked patch loses connectivity,<br>**When** the user views the dashboard,<br>**Then** the system displays an "Offline" warning with the last known timestamp. | EP03 |
| US13 | View patient location | As a Caregiver, I want to view the patient's real-time GPS location on a map so that I can know exactly where they are in case of an anomaly. | **Scenario 1:** GPS available.<br>**Given** that the user navigates to the patient list,<br>**When** they request the location view,<br>**Then** the system displays a map centered on the current coordinates.<br><br>**Scenario 2:** GPS unavailable.<br>**Given** that the patch cannot secure a GPS signal,<br>**When** the user requests the location,<br>**Then** the system shows the last known location and a "Signal Lost" indicator. | EP03 |
| US14 | Configure accessibility | As a User, I want to configure the language, font size, and background color so that I can adapt the platform to my visual needs. | **Scenario 1:** Font scaling.<br>**Given** that the user opens the accessibility menu,<br>**When** they select a larger font size,<br>**Then** the system immediately scales up the text across the interface.<br><br>**Scenario 2:** High contrast.<br>**Given** that the user opens the accessibility menu,<br>**When** they toggle high-contrast mode,<br>**Then** the system updates the CSS variables to high-visibility colors. | EP02 |
| US15 | Daily summary view | As a Patient, I want to view a daily summary so that I know if I'm stable. | **Scenario 1:** Data exists.<br>**Given** that a patient has active records,<br>**When** they request the summary view,<br>**Then** the system shows the last 24h records in a chart.<br><br>**Scenario 2:** Empty state.<br>**Given** that a new patient has no recorded data,<br>**When** they request the summary view,<br>**Then** the system displays an empty state message prompting them to link a patch. | EP03 |
| US16 | Configure notifications | As a User, I want to toggle email and push notifications on or off so that I can choose how I receive medical alerts. | **Scenario 1:** Disable push.<br>**Given** that the user is in the settings view,<br>**When** they disable push alerts,<br>**Then** the system saves the preference and revokes device token targeting.<br><br>**Scenario 2:** Enable email.<br>**Given** that the user is in the settings view,<br>**When** they enable email alerts,<br>**Then** the system subscribes their registered address to the mailing service. | EP05 |
| US17 | Submit support ticket | As a User, I want to submit a support form if I have an issue with the app so that the technical team can help me. | **Scenario 1:** Valid submission.<br>**Given** that a user accesses the Help section,<br>**When** they submit a topic and description,<br>**Then** the system registers the ticket and confirms reception.<br><br>**Scenario 2:** Empty description.<br>**Given** that a user accesses the Help section,<br>**When** they attempt to submit without a description,<br>**Then** the system prevents submission and highlights the required field. | EP02 |
| US18 | Link patient | As a Doctor, I want to link a patient so that I can monitor them. | **Scenario 1:** Valid code.<br>**Given** that a doctor is adding a patient,<br>**When** a valid linking code is submitted,<br>**Then** the system creates the relationship.<br><br>**Scenario 2:** Expired code.<br>**Given** that a doctor is adding a patient,<br>**When** an expired linking code is submitted,<br>**Then** the system rejects the request and prompts the patient to generate a new code. | EP04 |
| US19 | View patient list | As a Doctor, I want to see my patients so that I can manage workload. | **Scenario 1:** Populated list.<br>**Given** that a doctor has linked patients,<br>**When** they access the directory,<br>**Then** the system lists the linked patients.<br><br>**Scenario 2:** Empty directory.<br>**Given** that a new doctor has no linked patients,<br>**When** they access the directory,<br>**Then** the system displays an onboarding message to link their first patient. | EP04 |
| US20 | View patient history | As a Doctor, I want to view vital trends so that I can assess progress. | **Scenario 1:** Standard range.<br>**Given** that a doctor selects a patient,<br>**When** they request historical data,<br>**Then** graphs for the last 30 days are shown.<br><br>**Scenario 2:** Custom range.<br>**Given** that a doctor is viewing the history,<br>**When** they filter by a specific custom date range,<br>**Then** the system updates the graphs to reflect only that period. | EP04 |
| US21 | View placement tutorial | As a User, I want to see a visual guide on how to place and link the patch so that I can configure the device correctly. | **Scenario 1:** Linear progression.<br>**Given** that the user accesses the placement section,<br>**When** the view loads,<br>**Then** the system displays step-by-step instructions.<br><br>**Scenario 2:** Skipping guide.<br>**Given** that an experienced user accesses the tutorial,<br>**When** they select the skip option,<br>**Then** the system dismisses the guide and routes them to the dashboard. | EP03 |
| US22 | Remove patient | As a Doctor, I want to unlink patients so that I can manage active cases. | **Scenario 1:** Confirmed removal.<br>**Given** that a doctor selects to unlink a patient,<br>**When** removal is confirmed,<br>**Then** the system deletes the relationship without data loss.<br><br>**Scenario 2:** Cancelled removal.<br>**Given** that a doctor is prompted to confirm unlinking,<br>**When** they cancel the action,<br>**Then** the relationship remains active and unchanged. | EP04 |
| US23 | Automatic alert | As a Doctor, I want alerts for abnormal metrics so that I can act quickly. | **Scenario 1:** Critical threshold.<br>**Given** that the system monitors incoming data,<br>**When** an abnormal value is detected,<br>**Then** the system sends a high-priority notification.<br><br>**Scenario 2:** Normal threshold.<br>**Given** that the system monitors incoming data,<br>**When** values remain within normal ranges,<br>**Then** no alert is triggered and data is silently logged. | EP05 |
| US24 | Measurement reminder | As a Patient, I want reminders so that I maintain routine. | **Scenario 1:** Scheduled trigger.<br>**Given** that a patient has a scheduled measurement,<br>**When** the time arrives,<br>**Then** a notification is sent to their device.<br><br>**Scenario 2:** Dismissed reminder.<br>**Given** that a reminder notification is active,<br>**When** the patient dismisses it without taking action,<br>**Then** the system logs the reminder as skipped in the adherence report. | EP05 |
| US25 | Mark notifications read | As a User, I want to mark alerts as read so that I stay organized. | **Scenario 1:** Bulk action.<br>**Given** that a user has unread alerts,<br>**When** they confirm marking all as read,<br>**Then** the status updates and the notification badge clears.<br><br>**Scenario 2:** Single action.<br>**Given** that a user is viewing the alert list,<br>**When** they interact with a single unread alert,<br>**Then** only that alert is marked as read and the badge count decreases by one. | EP05 |
| US26 | Monthly report PDF | As a Patient, I want to export my history so that I can share it. | **Scenario 1:** Successful export.<br>**Given** that a patient views their history,<br>**When** they request an export,<br>**Then** the system generates and downloads a PDF.<br><br>**Scenario 2:** Export failure.<br>**Given** that a patient requests an export,<br>**When** the generation service times out,<br>**Then** the system displays an error prompt and suggests trying again later. | EP06 |
| US27 | Patient report | As a Doctor, I want consolidated alerts so that I can analyze cases. | **Scenario 1:** Anomaly summary.<br>**Given** that a doctor reviews a case,<br>**When** they request a report,<br>**Then** the system generates a document compiling all alerts.<br><br>**Scenario 2:** Clean report.<br>**Given** that a doctor requests a report for a stable patient,<br>**When** the system generates it,<br>**Then** the report indicates zero anomalies for the selected period. | EP06 |
| US28 | Subscription plan selection | As a Patient, I want premium access so that I get full features. | **Scenario 1:** Approved payment.<br>**Given** that a user submits an upgrade request,<br>**When** the payment method is validated,<br>**Then** the system activates premium features.<br><br>**Scenario 2:** Declined payment.<br>**Given** that a user submits an upgrade request,<br>**When** the card has insufficient funds,<br>**Then** the gateway declines the charge and the system displays an error. | EP07 |
| US29 | Update payment method | As a Patient, I want to update my card so that service is uninterrupted. | **Scenario 1:** Valid new card.<br>**Given** that a Premium user manages billing,<br>**When** they submit valid new card details,<br>**Then** the system updates the method.<br><br>**Scenario 2:** Expired card.<br>**Given** that a Premium user manages billing,<br>**When** they submit an expired card,<br>**Then** the system rejects the update and prompts for valid credentials. | EP07 |
| US30 | Cancel subscription | As a Patient, I want to cancel my plan so that I stop service. | **Scenario 1:** Confirmed cancellation.<br>**Given** that a Premium user wishes to cancel,<br>**When** confirmation is provided,<br>**Then** the system schedules cancellation for the cycle end.<br><br>**Scenario 2:** Retained subscription.<br>**Given** that a user initiates cancellation,<br>**When** they accept a retention offer instead,<br>**Then** the premium subscription remains active. | EP07 |
| US31 | User registration service | As a Developer, I want a service to create users so that data is stored. | **Scenario 1:** Valid payload.<br>**Given** a valid JSON payload at the endpoint,<br>**When** the API processes it,<br>**Then** it saves the user and returns 201 Created.<br><br>**Scenario 2:** Malformed payload.<br>**Given** an invalid JSON payload,<br>**When** the API receives it,<br>**Then** it aborts processing and returns 400 Bad Request. | EP08 |
| US32 | Authentication service | As a Developer, I want authentication so that users are validated. | **Scenario 1:** Valid credentials.<br>**Given** valid login credentials in the request,<br>**When** the service authenticates them,<br>**Then** it issues a secure JWT and returns 200 OK.<br><br>**Scenario 2:** Invalid credentials.<br>**Given** incorrect login credentials,<br>**When** the service attempts authentication,<br>**Then** it returns a 401 Unauthorized status. | EP08 |
| US33 | Metrics service | As a Developer, I want to store vital signs so that history is tracked. | **Scenario 1:** Valid schema.<br>**Given** valid biometric data from the IoT device,<br>**When** it hits the ingestion endpoint,<br>**Then** the system stores it and returns 201 Created.<br><br>**Scenario 2:** Invalid schema.<br>**Given** biometric data missing required fields,<br>**When** it hits the endpoint,<br>**Then** the system rejects it and returns 422 Unprocessable Entity. | EP08 |
| US34 | Metrics retrieval service | As a Developer, I want to fetch history so that UI can display it. | **Scenario 1:** Authorized request.<br>**Given** an authorized GET request for metrics,<br>**When** processed,<br>**Then** the system returns the JSON data with 200 OK.<br><br>**Scenario 2:** Unauthorized request.<br>**Given** a GET request lacking a valid Bearer token,<br>**When** processed,<br>**Then** the system denies access and returns 401 Unauthorized. | EP08 |
| US35 | Linking service | As a Developer, I want to link users so that relationships exist. | **Scenario 1:** Valid code execution.<br>**Given** a valid linking code payload,<br>**When** approved by the service,<br>**Then** the system links records and returns 200 OK.<br><br>**Scenario 2:** Expired code execution.<br>**Given** an expired linking code payload,<br>**When** processed,<br>**Then** the system rejects the link and returns 404 Not Found. | EP08 |
| US36 | Patient listing service | As a Developer, I want listing service so that doctors see patients. | **Scenario 1:** Populated relation.<br>**Given** a valid request for a doctor's patients,<br>**When** executed,<br>**Then** the system returns the list as a JSON array.<br><br>**Scenario 2:** Empty relation.<br>**Given** a valid request for a doctor with no patients,<br>**When** executed,<br>**Then** the system returns an empty JSON array with 200 OK. | EP08 |
| US37 | Alert service | As a Developer, I want alert engine so that emergencies are handled. | **Scenario 1:** Threshold breached.<br>**Given** an abnormal metric event,<br>**When** processed by the engine,<br>**Then** the system logs it and publishes a notification event.<br><br>**Scenario 2:** Normal baseline.<br>**Given** a normal metric event,<br>**When** processed by the engine,<br>**Then** the engine safely ignores the event without triggering notifications. | EP08 |
| US38 | Profile update service | As a Developer, I want update functionality so that data stays current. | **Scenario 1:** Valid PATCH.<br>**Given** a valid profile update payload,<br>**When** the PATCH request is processed,<br>**Then** the system saves changes and returns 200 OK.<br><br>**Scenario 2:** Restricted field.<br>**Given** a payload attempting to modify a protected field (e.g., ID),<br>**When** processed,<br>**Then** the system ignores the restricted field and updates the rest. | EP08 |
| US39 | Subscription service | As a Developer, I want payment processing so that plans are activated. | **Scenario 1:** Webhook success.<br>**Given** an approved payment webhook,<br>**When** received,<br>**Then** the system upgrades the account in the database.<br><br>**Scenario 2:** Webhook failure.<br>**Given** a failed payment webhook,<br>**When** received,<br>**Then** the system logs the failure and downgrades the account role if necessary. | EP08 |
| US40 | PDF report service | As a Developer, I want report generation so that documents are created. | **Scenario 1:** Data aggregation.<br>**Given** a valid generation request,<br>**When** processed,<br>**Then** the system generates the PDF stream.<br><br>**Scenario 2:** Missing data.<br>**Given** a generation request for a period with no data,<br>**When** processed,<br>**Then** the service returns a 204 No Content response instead of a blank file. | EP08 |
